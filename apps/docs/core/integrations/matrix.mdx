---
title: Matrix
description: Send task notifications from Kaneo into Matrix via a bot account, either by letting Kaneo create spaces and rooms per project or by posting to a room you manage.
---

Kaneo can post task activity to a Matrix room whenever events occur in a project. Unlike webhook-based integrations, the Matrix integration logs into your homeserver as a bot user and works in one of two connection modes: it can create a small room structure for you (one space per workspace, one subspace per project, and Updates and General rooms inside it), or it can join an existing room that you already manage.

## Create a bot account

You need a Matrix user account that Kaneo can use. The exact steps depend on your homeserver.

- Synapse: create a dedicated user through the admin API or your admin UI, for example `POST /_synapse/admin/v1/users` with `admin: false`.
- Homeservers with registration enabled: register a normal account through your Matrix client, for example `@kaneo-bot:example.org`.
- Managed hosting: check your provider's documentation for creating additional users.

The account does not need administrator privileges. Kaneo never asks for the bot user ID: when you connect, it verifies the access token against the homeserver and discovers the user ID of the bot account automatically.

## Get an access token

1. Log in to the account with a Matrix client of your choice.
2. Open the client's settings and copy the account's access token.
3. Alternatively, request one directly from the login endpoint:

```
POST https://your-homeserver.example.org/_matrix/client/v3/login
```

```json
{
  "type": "m.login.password",
  "identifier": {
    "type": "m.id.user",
    "user": "kaneo-bot"
  },
  "password": "your-bot-password"
}
```

The `access_token` field in the response is what Kaneo needs.

<Warning>
Treat the access token like a password. Anyone with the token can act as the bot user. Consider giving the account a long random password you never reuse, and rotate the token if it leaks.
</Warning>

## Connect Matrix in Kaneo

1. Open **Settings** in the sidebar.
2. Under **Projects**, select the project you want to connect.
3. Open the **Integrations** tab.
4. Expand the **Matrix** section.
5. Enter your homeserver URL, for example `https://matrix.example.org`.
6. Paste the access token.
7. Choose a connection mode: **Create Kaneo spaces and rooms** or **Use an existing room**.
8. Depending on the mode, set the room options described below.
9. Choose which events to subscribe to.
10. Click **Connect Matrix**.

Kaneo validates the homeserver URL format and the access token, checks that the homeserver points at a public network destination, and verifies the credentials against the homeserver before saving. In provision mode the whole space and room structure is created during the connect request, so a misconfigured homeserver fails immediately instead of at the first notification. Once connected you can enable or disable the integration with the toggle, update event subscriptions, rotate the token, or disconnect entirely.

Self-hosted instances: requests to loopback or private network addresses are rejected unless your operator sets `KANEO_ALLOW_PRIVATE_WEBHOOK_DESTINATIONS`.

## Connection modes

### Create Kaneo spaces and rooms

Kaneo provisions the structure on your homeserver. Use the space name prefix to adjust how the top-level space is named, optionally nest the workspace space under a parent space by entering its room ID or alias, and list extra Matrix user IDs to invite into every created space and room.

Task updates are posted to the Updates room. The General room is created next to it as a discussion room for your team; Kaneo does not post into it.

### Use an existing room

Enter the room ID (`!abc123:example.org`) or alias (`#kaneo-updates:example.org`) of a room you manage. Kaneo resolves the alias, joins the room with the bot account, and posts all task updates there. The bot account must be able to join: invite it beforehand or make the room publicly joinable.

The connection mode and the target room (or parent space) are fixed once connected. To switch modes or rooms, disconnect and connect again.

## Room structure

In provision mode, Kaneo creates the following structure during the connect request using stable, deterministic room aliases:

- A space named `<prefix> · <workspace name>` with the alias `#kaneo-ws-<workspaceId>:<server>`.
- A subspace for the project with the alias `#kaneo-project-<projectId>:<server>`.
- A notification room named `<project name> — Updates` with the alias `#kaneo-project-<projectId>-updates:<server>`.
- A discussion room named `<project name> — General` with the alias `#kaneo-project-<projectId>-general:<server>`.

The project subspace is linked as a child of the workspace space, each room as a child of the subspace, and if you set a parent space, the workspace space as a child of that parent. Because aliases are deterministic, the structure is created once and reused; if a room already exists, Kaneo resolves the alias instead of creating a duplicate.

Created rooms are set up for team use: all members can post and invite (`users_default`, `events_default`, and `invite` power levels are 0), so people you invite can participate without needing elevated permissions.

Users listed under **Invite users** are invited to all four rooms as they are created. You can add members later directly in your Matrix client.

When the structure is ready, the bot posts a short welcome notice into the Updates room confirming the project it will report on.

## Supported events

| Event | Default | Description |
| --- | --- | --- |
| Task created | On | A new task is created in the project |
| Task status changed | On | A task moves to a different status column |
| Task priority changed | Off | A task's priority is changed |
| Task title changed | Off | A task's title is edited |
| Task description changed | Off | A task's description is edited |
| Task comment created | On | A new comment is added to a task |
| Task deleted | On | A task is deleted |
| Task moved | On | A task is moved to a different project or workspace |
| Task due date changed | On | A task's due date is set or changed |
| Task assignee changed | On | A task is assigned to a user |
| Task unassigned | Off | A task's assignee is removed |

You can change these toggles at any time in the integration settings.

## Message format

Kaneo sends notices with formatted content that includes:

- The event title
- A direct link to the task in Kaneo
- Project, status, and priority details
- The name of the user who triggered the event when available

Make sure [`KANEO_CLIENT_URL`](/core/installation/environment-variables) is set to your public Kaneo URL so task links work correctly.

## Updating credentials

To rotate the access token after connecting, paste a new token in the token field and click **Save Changes**. If you leave the token field empty, Kaneo keeps the currently stored token. Whenever the homeserver URL or token changes, Kaneo re-verifies the credentials against the homeserver before saving.

You can also update the space name prefix, invited users, and event subscriptions at any time. Changing the homeserver means the existing room structure on the old server is no longer used.

## Disconnecting

Click Disconnect to remove the integration. This deletes the stored Matrix configuration for that project, but does not delete any rooms or spaces on your homeserver. You can reconnect at any time; in provision mode Kaneo will reuse the existing rooms through their aliases.
